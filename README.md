## 2. C# — Langage & Fonctionnement

### 2.1 Syntaxe & Bases
- **Types valeur vs référence** : `struct`, `int`, `bool` (valeur) vs `class`, `string`, `object` (référence).
- **Nullables** : `int?`, `string?`, opérateurs `?.`, `??`, `??=`.
- **Propriétés** : auto-properties, expression-bodied members, `init`, `required`.
- **Pattern matching** : `is`, `switch` expressions, `when`.
- **Records** : types immuables avec égalité structurelle.

### 2.2 Fonctionnement interne
- **🗑️ GC (Garbage Collector)** : Gère automatiquement la mémoire (3 générations 0, 1, 2 + LOH). Libère les objets non référencés. Modes Workstation/Server. `IDisposable` pour ressources non managées.
- **⚙️ IL (Intermediate Language)** : Code compilé par le compilateur C#, indépendant de la plateforme, stocké dans assemblies (`.dll`, `.exe`), lu par le CLR.
- **🔥 JIT (Just-In-Time)** : Compile l'IL en code machine à l'exécution, optimisé pour la plateforme cible, méthode par méthode.
- **🚀 AOT (Ahead-Of-Time)** : Compilation native avant exécution sans JIT runtime. Démarrage plus rapide, idéal pour containers, mobile, IoT (Native AOT en .NET 7+).

```csharp
// Exemple : GC et IDisposable
public class ResourceHolder : IDisposable
{
    private bool _disposed = false;

    public void Dispose()
    {
        Dispose(true);
        GC.SuppressFinalize(this);
    }

    protected virtual void Dispose(bool disposing)
    {
        if (!_disposed)
        {
            if (disposing) { /* libérer ressources managées */ }
            // libérer ressources non managées
            _disposed = true;
        }
    }
}
```

## 4. Collections .NET

### 4.1 Collections génériques (System.Collections.Generic)

| Collection | Description | Accès / Complexité | Cas d'usage principal |
| :--- | :--- | :--- | :--- |
| `List<T>` | Tableau dynamique redimensionnable | Index O(1) | Collection ordonnée, accès rapide par index |
| `Dictionary<K,V>`| Table de hachage clé-valeur | Clé O(1) | Recherche rapide par clé unique |

| `ConcurrentDictionary`| Dictionnaire thread-safe | O(1) | Accès concurrent en environnement multi-thread |

## 5. LINQ & Sérialisation

### 5.1 LINQ (Language Integrated Query)
Permet d'interroger des collections en mémoire, bases de données ou XML avec une syntaxe unifiée (méthode vs requête, exécution différée).

```csharp
// Syntaxe méthode
var result = users
    .Where(u => u.Age > 18)
    .OrderBy(u => u.Name)
    .Select(u => new { u.Name, u.Email })
    .ToList();
```

### 5.2 Sérialisation
- **JSON** : `System.Text.Json`, `Newtonsoft.Json` (standard web, léger).
- **Protobuf** : `Google.Protobuf` (très compact, rapide, binaire).
- **MessagePack** : Binaire compact et rapide.

## 6. Asynchronisme & I/O

Utilisation de `async` / `await` pour les opérations I/O et réseau sans bloquer le thread principal.

```csharp
public async Task<User> GetUserAsync(int id, CancellationToken ct = default)
{
    var response = await _httpClient.GetAsync($"/api/users/{id}", ct);
    response.EnsureSuccessStatusCode();
    var json = await response.Content.ReadAsStringAsync(ct);
    return JsonSerializer.Deserialize<User>(json)!;
}
```

## 7. Principes de Développement

- **S** : Single Responsibility Principle (une classe = une responsabilité).
- **O** : Open/Closed Principle (ouvert à l'extension, fermé à la modification).
- **L** : Liskov Substitution Principle (substitution des sous-classes).
- **I** : Interface Segregation Principle (interfaces spécifiques).
- **D** : Dependency Inversion Principle (dépendre des abstractions).
- **YAGNI** : You Aren't Gonna Need It.
- **KISS** : Keep It Simple, Stupid.
- **DRY** : Don't Repeat Yourself.

```csharp
[TestFixture]
public class UserServiceTests
{

    private UserService _service;

    [SetUp]
    public void Setup()
    {
        _repoMock = new Mock<IUserRepository>();
        _service = new UserService(_repoMock.Object);
    }

    [Test]
    public async Task GetUser_ExistingId_ReturnsUser()
    {
        var user = new User { Id = 1, Name = "Alice" };
        _repoMock.Setup(r => r.GetByIdAsync(1)).ReturnsAsync(user);

        var result = await _service.GetUserAsync(1);

        Assert.That(result, Is.Not.Null);
        Assert.That(result.Name, Is.EqualTo("Alice"));
    }
}
```

## 26. 🚫 À ne pas faire dans votre code (Anti-patterns)

- **Méthodes fleuves & God classes** : Diviser les responsabilités, garder les méthodes courtes (<20 lignes).
- **Gestion des erreurs** : Ne jamais avaler les exceptions (`catch (Exception) {}`) ni perdre la stack trace (`throw ex;`). Utiliser <code>throw;</code>.
- **Async/Await** : Bannir `.Result` ou `.Wait()` (risques de deadlocks). Éviter `async void` (sauf event handlers).
- **Sécurité** : Éviter la concaténation SQL (utiliser des requêtes paramétrées), ne jamais stocker de secrets en clair dans le code ou les fichiers de configuration.

## 27. ✨ Comment écrire un code propre qui vous différencie

1. **Auto-documentation** : Noms de variables et méthodes explicites qui racontent une histoire métier.
2. **Guards clauses** : Valider les préconditions en haut de méthode pour éviter l'imbrication excessive (`if (...) return;`).
3. **Immuabilité par défaut** : Utiliser `readonly`, `record` et des types immuables pour éliminer les effets de bord indésirables.
4. **Tests pertinents** : Écrire des tests unitaires et d'intégration lisibles qui servent aussi de documentation vivante.
5. **Veille et rigueur** : Rester curieux des évolutions du langage (.NET 8/9, C# 13) tout en appliquant les fondamentaux intemporels (SOLID, KISS).
